# SMART Exchange — variant c000 (EXAMPLE)

> **Worked example, not a real client.** `c000` is reserved to show the pattern. Agents: do not
> implement this. Use it as a model for real variant files.

Behavior = standard R3 ([standard.md](../standard.md), [changelog](../changelog.md)) **plus** the deltas below.

## Deltas vs standard R3

- `[integration]` Every bank account added in **Payment Preferences** is sent to an **external
  verification provider** before it can be used to receive payments.
  Standard R3 has no external check (it only has the micro-deposit "verify deposit" dialog).
- `[layout]` Each bank account row in Payment Preferences shows a **verification status badge**:

  | Status | Meaning | Badge (design system) | Account usable? |
  |---|---|---|---|
  | Verified | Provider confirmed the account | green | Yes |
  | Verification in progress | Waiting for the provider | yellow | No |
  | Verification failed | Provider rejected the account | red, with reason + "Edit account" action | No |

- `[flow]` A newly added account starts as **Verification in progress**. It cannot be set as default
  or selected for a payout until **Verified**.
- `[content]` Helper text under "Add bank account": explains that the account will be verified by a
  third party and how long it usually takes. TODO: final copy.

## Code on the client branch

- `src/scripts/pages/payment-preferences-page.js`: status badge and gating.
- `src/scripts/payment-preferences-components.js`: bank account row builder.
- `src/data/bank-accounts.json`: new field `verificationStatus`: `"verified" | "in_progress" | "failed"`,
  plus `verificationFailureReason`.

## Not present on this variant

Standard features added after R3 that this client does **not** have yet:

- none (R3 is the latest standard)

## Upstream notes

`maybe`: account verification status is likely useful for other clients. If upstreamed, standard should
define the badge as a reusable component and make the provider configurable.

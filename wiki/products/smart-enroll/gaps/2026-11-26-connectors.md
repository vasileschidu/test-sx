## Conflicts R1 vs SE (decision needed; R1 wins by rule unless noted)

- C1 ERP connect length: R1 = 3 steps (provider, sign in, Pending Verification + Validate Connection). SE = 2 steps (provider "Step 1 of 3", sign in "Step 2 of 3", header still says 3) then a "One step closer!" submitted dialog. Both say "of 3", so SE step 3 is likely the validation step that moved elsewhere. Code follows R1.
- C2 ERP sign-in fields: R1 User ID / Password / Company; SE Username / Company / Password (frame 5360:343203).
- C3 Bank table: SE has extra column "Connection Name"; R1 (per wiki) does not list it.
- C4 Data Source Preferences (3 cards: ERP / Batch / API, "Current connection", "Information will be lost"): exists in R1 only. SE Integration tab shows two plain sections "Accounting Software" and "Bank Account". Code follows R1. Batch/API have no SE states at all.
- C5 Bank wizard: R1 select "Who do you bank with?" + 2 sign-in steps + "Name Your Bank Account"; SE tile grid step 1 of 3, tile step, fields, credentials step with Connection Name / Provider ID Reporting / Application ID Reporting; bank list in SE lacks Goldman Sachs and Jack Henry (R1 has 6 banks incl. both).
- C6 Bank result: R1 = Please wait -> table; SE = Please wait -> Successful connection modal (1406:340672) -> table; also Failed (1409:395312).
- C7 Disconnect copy: R1 API "Are you sure you want to disconnect?"; SE ERP "Disconnect ERP / Are you sure you want to disconnect the ERP?". Not a true conflict (different object); apply SE copy to ERP only.
- C8 Section titles when connected: SE "Your ERP/software accounts" (lowercase s) / "Your bank accounts"; code "Your ERP/Software accounts" / "Your Bank Accounts" (R1 casing per wiki). R1 wins.
- C9 Warning alert wording: SE "...missing the Quickbooks Bank Account Name... Please select one from the list." vs code (R1) "...Please add one."

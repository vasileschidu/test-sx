SMART Figma Audit

How the SMART Disburse, Consumer Portal, Supplier Portal, SMART Hub and SMART System Figma files are organised, where the same modules are designed more than once, and how the copies disagree.

Summary

What we found

  • The same modules are designed again in many files.Get Paid has copies in 23 files, Login and verification in 16, Payment Preferences in 13. The copies disagree on fields, labels, steps and states.
  • Newer work has not reached the main files.Bank verification states live only in Account Validation. The full OTP set lives only in a [DEV] file, not in the launched Default Flow. The SMART Exchange network invite lives only in SX Configurable Items.
  • Old releases cannot be archived yet.[R1] Accounts Payable still holds flows that [R2] lacks. [R2] SMART Exchange holds the KYB banner and Business Instances that [R3] lacks.
  • Drafts outweigh designs in many files.7 files keep half or more of their screens on draft, archive or sandbox pages, with no marker of which version is current.
  • Status labels no longer mean much.28 files are marked [REVIEW], [WIP] or [DEV] but have not been touched for six months or more. Two labelling systems run side by side: stage tags and release numbers.
  • Components and words drift.Many SMART Hub files re-create library components locally. The same thing is called “Payer’s Card”, “Accept Card Payment” or “Quick Pay”; “Company”, “Business” or “Organisation”; and the password minimum is 8, 12 or 15 characters depending on the screen.

Method

How this was done

Every file in the five product folders was read through the Figma API on 16 Oct 2026. Two were skipped on request: [ARCHIVE] SX | Onboarding with Payment and Color Tokens/DLT.

  • For each file, every top-level screen was summarised: its visible text, component instances and size. A file review then mapped the screens to product modules and listed organisation problems.
  • For the nine modules that matter most, a comparison review set the copies side by side by fields, labels, states, actions and components, and picked a source of truth.
  • Screen counts per module are approximate: some screens belong to more than one module, and files that nest sections inside sections were compared at section level.
  • Detached components were judged by specific component names only; generic names were ignored.
  • Nothing was changed in Figma.
